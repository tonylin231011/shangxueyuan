# Changelog

## v1.2 — 规则注册表、历史棋谱fixture与史实补齐（开发中）

- 将事件状态变化改为预登记规则注册表：事件只提交 rule_id 与输入，状态由可执行规则函数计算；规则参数在运行时只读。
- 增加确定性事件提交顺序：sim_time → sequence → event_id；并显式记录并行组和事件依赖。
- 指数计算要求匹配基期和基准值；证据分级不再使用“非随机=描述性”的单一布尔判断。
- 增加NPC触发评估记录，覆盖触发与未触发原因。
- 将V1.0 MOVE 001–005回填为首个fixture；保留MOVE 003成本冲突、MOVE 004子行动单价缺失和MOVE 002并行任务粒度缺口。
- 从原始V1.0分支逐字复制六份关键原始文件至 archive/v1.0/，并记录原始blob SHA；根目录维护文件与历史快照分离。
- 补充顾客分层数据勾稽、培训试点基线缺口、产品毛利/连带率缺口登记。
- 将真实历史时间线与本局模拟时间线分开；将FY2008公开目标及美国业务交易趋势纳入开局材料。
- 重新核验1月7日、1月11日和1月30日Starbucks Archive员工信PDF链接；截至2026-11-17可打开，并补充可检索标题与页码定位。
- 新增GitHub Actions单元测试工作流；首次CI发现旧版engine/__init__.py仍导入已删除的StateChange，已更新V1.2导出接口并提交修复，等待复跑结果。
- 将INDEX中的“基准档案”更正为“原始档案”。

### V1.2边界

当前策略分支规则使用预登记课堂假设参数，仅用于验证同一规则集能否对不同策略输入产生不同、可复现的路径；不代表真实星巴克因果模型，也不决定哪条路径更优。V1.2尚未通过独立Muse复核或V1.3 A5反历史策略压力测试。


## v1.1 — 审计、引擎设计与最小原型

- 新增 `audit-findings-v1.1.md`，将问题分为P0/P1/P2，并给出可验收修复要求。
- 新增 `engine-design-v1.1.md`，定义历史事实层、玩家信息层、世界状态层、事件账本和呈现层。
- 新增 `engine/core.py`：确定性事件应用、状态前置条件校验、资源扣减、事件回放、旧账本冲突审计和指数乘积计算。
- 新增8项自动化单元测试，覆盖事件回放、资源差异、指数运算、时间排序、重复事件、资源不足和状态前置条件。
- 明确历史日期、模拟时钟、史料公开时间与玩家可见时间必须分离。
- 明确角色历史任职事实与模拟角色场景分离。
- 规定状态变化必须通过事件账本；资源、日历时间和组织执行能力分别结算。
- 设计证据质量字段、NPC触发规则、分支快照和回放机制。
- 使用SEC FY2007 10-K、2008年1月7日SEC公告及1月7日/11日员工信核验核心历史指标与领导职务，并修正Martin Coles任职时间边界的审计表述。
- 核验关键历史数据与领导职务的SEC来源和口径；V1.1未将SEC网页行号范围完整落档，V1.2继续补充来源定位与美国业务/公司合并口径区分。
- 保留V1.0全部原始棋谱与已知错误，不静默修正。

### V1.1 状态声明

已完成档案审计、引擎设计规范和最小可运行原型。当前原型不是完整模拟器，不生成商业证据、不规划NPC行动，也不是经过真实星巴克数据校准的经营模型。

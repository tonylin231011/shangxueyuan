# 独立 AI 审阅任务书｜商业残局 01：星巴克 2008

## 审阅目标

请独立审查本课程资料，目标不是赞美课程或给出泛泛建议，而是找出可能损害历史真实性、模拟公平性、因果推理和教学价值的问题，并提出可执行的修订方案。

请先阅读：
1. README.md
2. scenario.md
3. historical-record.md
4. simulation-rules.md
5. simulation-data.md
6. decision-log.md
7. debrief.md

## 必须遵守的边界

- 不得把S｜模拟创作数据说成星巴克真实内部数据。
- 不得把模拟角色对话或访谈当作真实原话。
- 不得补造历史事实、未发生的玩家决策或缺失的统计定义。
- 不得在审阅意见中假设玩家已完成最终战略决策。
- 对历史事实纠错必须附一手来源、准确段落或页码及口径说明。
- 对模拟建议必须明确它是模拟设计判断，不是历史事实判断。

## 审阅维度与具体问题

### A. 历史真实性与时间边界

1. FY2007收入、同店销售增长、客单价贡献、交易笔数贡献、营业利润率和门店数是否准确？
2. 2008-01-07、01-11、01-30的公开文件被正确放置在时间线上了吗？
3. 玩家扮演Howard Schultz时，模拟切片与CEO任命公告的时间关系是否清楚？
4. 是否把后来才披露的信息提前给玩家？
5. 课程中的管理层分工和角色名是否有可信来源？

请提供纠错表：文件/原句/问题/可靠来源/建议替换。

### B. 商业逻辑与模拟真实性

1. 顾客交易频率、顾客流失、客单价和销售额的数据关系是否自洽？
2. “活跃顾客数下降”与“永久流失”是否被正确区分？
3. 门店内部蚕食和竞品影响的调查设计是否能区分原因？
4. 产品精简决策是否考虑毛利、品牌价值、产品搭配、供应链和顾客细分？
5. 门店培训的业务机制是否合理？
6. 单店单位经济与区域组合收益的比较是否缺少重要变量？
7. 管理层角色是否有独立目标、激励和真实反对意见？

### C. 数据与因果推理

1. 是否有错误的计算、指标定义、基准期或图表口径？
2. 试点和对照组的数据是否能支持页面中的结论？
3. 哪些结论属于描述性观察，哪些只是相关性，哪些尝试作因果推断？
4. 应补充哪些样本、指标、实验设计、置信区间或敏感性分析？
5. 资源和时间结算是否一致？

### D. 教学价值

1. 是否真正让玩家自主诊断，而不是逐步引导到预设答案？
2. 玩家是否有足够信息做出合理选择？
3. 是否允许玩家提出模拟系统未列出的自由行动？
4. 行动成本是否真正构成机会成本？
5. 管理层反馈是否过度迎合玩家？
6. 是否在适当时点引入意外事件和非预期后果？
7. 是否能公平地区分决策质量与结果好坏？

### E. 产品与系统可复用性

1. 哪些规则可抽象为跨案例引擎？
2. 哪些机制过度依赖星巴克特定背景？
3. 如何实现状态快照、行动日志、可回放棋谱和反事实分支？
4. 哪些资料应结构化为JSON/YAML，哪些适合Markdown？
5. 如何管理史料版本、证据链接、事实标签和模拟参数？
6. 如何设计课程验收测试，避免后续案例出现相同缺陷？

## 输出格式

请按以下顺序给出：

### 1. 总体判断
- 最有价值的设计是什么？
- 当前最大的可信度风险是什么？
- 是否适合作为课程系统的第一课基准？为什么？

### 2. P0 致命问题
可能造成历史误导、关键数据错误或模拟不公平的问题。每条给出处、影响和修复方案。

### 3. P1 重要改进
明显影响训练价值、因果推理、执行或可复用性的改进。

### 4. P2 增强建议
交互、叙事、视觉、游戏化方面的优化。

### 5. 具体修订补丁
尽可能给出可直接应用的文件路径、替换文本、规则或结构化字段。

### 6. 下一版验收标准
提供可测试的标准，不要只给抽象原则。

### 7. 对其他审阅者的挑战
列出你认为最可能被忽略的反直觉问题。

## 特别挑战

请重点挑战以下假设：
- “收入增长、客单价上涨、交易笔数弱增长”是否足以推导出增长质量恶化？
- 是否把“复杂度”预设成问题，而没有先证明复杂度与顾客价值、门店生产率之间的净关系？
- 暂停扩张是合理风控，还是可能过度反应？
- 试点数据是否存在严重的选择偏差？
- 模拟的资源成本是否真的影响了玩家行为？
- 目前的玩家路径是否只是“听从教练安排”，而非独立决策？

请保持尖锐、具体、证据驱动。宁可指出课程基础不牢，也不要为了鼓励创作者而降低审阅标准。

# 模拟规则与参数（本局版本）

## 1. 设计目的

用有限时间、信息和资源，迫使玩家在事实不完整时做调查与经营选择。模拟结果服务于决策训练，而非声称精确重建星巴克真实历史。

## 2. 时间系统

- 入局切片：2008-01-07 07:30 PT（游戏时间戳，非历史会议时刻）。
- 模拟阶段：
  - 1月7日：入局与首次信息请求；
  - 1月8日至11日：顾客、区域门店和门店体验调查；
  - 1月11日至12日：COO会议、财务调取授权和扩张项目管控；
  - 1月12日至14日：执行产品审核、培训及扩张评估；
  - 1月14日至20日：观察阶段性执行结果。
- 原设定的经营方向交付日：1月30日。此日期是课程设定；真实历史上1月30日有Schultz员工沟通文件，不能将两者混同。
- 时间推进由行动和执行阶段驱动。未授权的行动不能自动发生；已批准任务可以在CEO暂时不下达新指令时继续执行。

## 3. 资源系统

### 初始参数（S）

| 资源 | 初始值 | 含义 |
|---|---:|---|
| CEO决策精力 | 12点 | 用于调查授权、重大决策与关键沟通 |
| 董事会信任 | 7/10 | 对CEO判断与执行的模拟支持程度 |
| 组织执行能力 | 8/10 | 组织吸收并执行变革的模拟能力 |
| 品牌信任指数 | 100 | 模拟顾客品牌感知基准 |
| 员工士气指数 | 100 | 模拟员工状态基准 |

所有数值均为游戏参数，不是历史测量数据。

### 资源概念应严格分开

- **CEO决策精力**：玩家有限的决策带宽，不等于真实工作小时。
- **日历时间**：模拟世界推进的时间。
- **组织执行能力**：团队在一定期间内承接行动的能力，不等于CEO个人资源。
- **资金/资本预算**：本局起初并未赋予明确数值，不得擅自把它当作已建模资源。
- **董事会信任、品牌信任、员工士气**：状态变量，变化需由行动和证据支持，不能仅因叙事需要而跳动。

## 4. 行动成本（初版）

| 行动 | 时间成本 | 决策精力 |
|---|---:|---:|
| 调取美国门店交易数据 | 0.5天 | 1点 |
| 调取门店单位经济数据 | 1天 | 1点 |
| 走访门店 | 1.5天 | 2点 |
| 访谈顾客 | 2天 | 2点 |
| 访谈COO | 0.5天 | 1点 |
| 访谈财务负责人 | 0.5天 | 1点 |
| 调查竞争对手 | 1.5天 | 1点 |
| 董事会战略沟通 | 0.5天 | 1点 |

成本表是模拟规则，不是现实工作量标准。MOVE 001将区域运营报告与COO答复合并为1.5天、2点执行；MOVE 002的三项调查合计按5点、3天结算。未来版本应把批量请求的成本计算规则明确化，避免事后估算。

## 5. 信息系统

模拟信息按可得性和质量区分：
- **L0：公开信息**，例如SEC年报、公司公告和公开员工信；
- **L1：管理层经营报表**，本局部分为模拟数据；
- **L2：门店、员工和顾客反馈**，本局抽样和引语为模拟创作；
- **L3：管理层顾虑、组织阻力和未公开内部动态**，除有公开史料支持外均属模拟创作。

每条信息必须附：
- 来源类型；
- 时间戳；
- 信息覆盖范围；
- 样本口径；
- 缺失与误差；
- H/K/S/I/U标签；
- 是否为玩家当时可见。

## 6. 状态变量

本局涉及的模拟指标：
- 顾客交易频率；
- 活跃顾客规模；
- 平均客单价；
- 门店单位经济；
- 品牌体验；
- 员工士气；
- 资本配置效率；
- 组织执行负荷；
- 高峰等待时间；
- 订单处理量与制作差错率。

尚未建立统一、可重复计算的状态转移公式。本局展示的数值是脚本化模拟反馈，不应声称由真实经营模型精确计算。

## 7. 决策记录要求

每次玩家行动至少记录：
1. 玩家原始指令（逐字）；
2. 行动时间与资源成本；
3. 行动前玩家可见的信息；
4. 玩家说明的目标与理由（如有）；
5. 执行者、执行范围与时间；
6. 新信息及其可信度；
7. 状态变化；
8. 其他可解释原因和混杂因素；
9. 被排除或尚未执行的替代选项。

玩家没有明确说明的动机，不得由教练补写。

## 8. 公平性和训练原则

- 不得在玩家决策前泄露后见之明。
- 不得通过隐藏的“标准答案”惩罚合理但不同的策略。
- 不得将结果好坏直接等同于决策质量。
- 允许玩家追问数据、质疑管理层、改变优先级和要求验证。
- 信息应有延迟、缺失、样本偏差和口径差异，但不能故意误导而不留可追溯线索。
- 发生模拟事件时必须记录触发原因；如果使用随机事件，应记录随机种子或至少记录事件抽取规则。
